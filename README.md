# 磁盘清理助手

C 盘快满了，却不知道该删什么？这个工具帮你看懂哪些东西占空间、哪些缓存可以清理，以及哪些文件先别动。

打开后先看「清理首页」，不需要先弄懂系统目录或专业术语。首页显示所选磁盘的剩余空间，并推荐下一步；上方可以切换 C 盘和 D 盘。

| 你想做什么 | 点哪里 |
|---|---|
| C 盘满了，先清理一点 | 首页「查看可清理项目」，确认内容后点「一键清理」 |
| 想知道是谁占空间 | 首页「看看谁占空间」，查看大文件和大文件夹 |
| 不知道这个文件夹能不能删 | 「文件夹」，查看用途以及「只清缓存 / 先确认用途 / 建议保留 / 不要删除」等建议 |
| 某个软件已经不用了 | 「已装软件」，选择软件后点击「卸载这个软件」 |
| 不想让软件开机就启动 | 「开机启动」默认看已开启的软件，也可切换已关闭、待确认，再打开 Windows 设置调整 |
| 游戏缓存或重要工程不想被清理 | 首页「保护游戏缓存」或「保护 EDA / 其他文件夹」 |
| 资料想留着，但 C 盘放不下 | 首页「迁移到 D 盘」，按检查、复制、校验、验证的步骤处理 |
| 想知道清完之后哪里又变大了 | 首页的空间变化入口，比较同一位置最近两次完整扫描 |

**打开软件和查看清单不会删除文件。** 缓存清理只处理你勾选的文件，删除后不经过回收站；照片、文档、备份和不认识的文件夹不会被自动当成垃圾。卸载软件可能影响其中的配置或存档，请先保存重要内容。

这里整理的是**存文件的磁盘空间**，不是运行软件的内存。文件很大不等于可以删除；找不到可清理缓存，也不代表整个磁盘都没有能整理的东西。软件不会承诺一键清理所有内容。

**下载**　到 [GitHub 发布页](https://github.com/yyt-serendipity/windows-disk-guide/releases/latest) 下载 `DiskGuide-1.10.0-windows.zip`，解压后双击 `磁盘清理助手.exe`。把同包的 `README.md` 和程序放在一起，可从窗口右下角「使用说明」离线阅读。

## 我的电脑能用吗？

| 环境 | 适用情况 |
|---|---|
| Windows 11 x64 桌面 | 已在 Windows 11 x64、系统内部版本 26100、.NET Framework 4.8.1、NTFS 上实际启动并验证。普通 Windows 账户即可使用。 |
| Windows 10 x64 桌面 | 设计上兼容，要求 .NET Framework 4.8 或 4.8.1。当前没有 Windows 10 实机验证记录。 |
| 只有 C 盘 | 可以使用。程序分别检测可用的本地固定 C、D 盘，缺少 D 盘时按 C 盘工作。 |
| 有 E、F 盘，或使用移动盘、网络盘 | 当前版本仅处理 Windows 标记为本地固定磁盘的 C、D。其他盘符、网络映射盘和标记为可移动的卷不进入清理范围。 |
| Windows ARM64、32 位 Windows、其他文件系统 | 尚未验证。程序以 AnyCPU 编译，仍依赖本机 WPF、Win32 文件 API 和文件系统返回的身份信息。 |
| macOS、Linux、无桌面的服务器 | 这个版本使用 Windows 图形界面和 Windows 专用文件接口，以上环境不属于运行目标。 |

目标运行时是 **.NET Framework 4.8**。仅安装新版 `.NET` 或 `dotnet` SDK 不能代替这个 Windows 组件。若启动失败，可在 PowerShell 执行下面的只读检查；`Release` 至少为 `528040` 表示已安装 4.8 或更高的 4.x 版本。[微软运行环境说明](https://learn.microsoft.com/en-us/dotnet/framework/install/on-windows-10) · [微软版本检测说明](https://learn.microsoft.com/en-us/dotnet/framework/migration-guide/how-to-determine-which-versions-are-installed)

```powershell
(Get-ItemProperty 'HKLM:\SOFTWARE\Microsoft\NET Framework Setup\NDP\v4\Full').Release
```

## 第一次使用

1. 默认打开「清理首页」，先看 C 盘剩余空间和清理建议。顶部可切换 C 盘或 D 盘。「文件夹」仍从所选磁盘的最外层开始，选中一项即可查看用途和能否删除；双击进入下一级。
2. **看清两个数字。**「占用空间」是能读取到的文件长度总和。「可清缓存」只计入当前符合默认规则、应用状态允许清理的文件。出现 `≥` 表示统计跳过了链接或受限位置。主要空间占用列出最多三个子项。
3. 只想清一个文件夹时，点「查看清理项」。清单顶部始终显示范围。用「建议清理」「先看影响」「先退出软件」切换类别，标签旁数字是这一范围内的项目数。「预计可清理」只统计当前类别里勾选的文件，点击「一键清理」也只处理这些文件。切回「全部项目」可看到先前的勾选；「查看整个磁盘」或切换磁盘可重置目录范围。
4. 选中一个清理项目，点「查看具体文件」，查看文件名、完整路径、大小、修改时间和该项目的入选依据。可搜索文件并取消个别勾选；「全选当前结果 / 取消当前结果」只作用于搜索后的可见结果。「保存文件选择」只保存选择，不立即删除。
5. 主页面的「预计可清理」按保存后的文件选择重新计算；清单「找到的大小」仍表示所有符合规则文件的总大小。结果栏显示实际删除的文件数、文件大小和跳过数。主动排除的文件不会算成清理失败。遇到「先退出软件」，先正常退出对应应用，再点「重新扫描」。

预览中的普通勾选只保存在本次程序会话中。重新扫描时，路径、文件身份、长度与修改时间均未变化的文件会保留排除选择；新文件或发生变化的文件会按新快照重新判断。关闭预览或点「取消」不会应用未保存的普通勾选。若需要以后也不清理某个位置，请使用下面的「永久保留规则」；这类规则点击添加时立即保存，不受预览取消按钮影响。所有实际缓存删除仍须通过原来的白名单、占用与文件身份复核。

**文件会永久删除，不经过回收站。** 如果某个文件夹显示「先确认用途」，可以查看子目录或在资源管理器中打开。软件没有提供将未知文件夹整夹加入删除清单的入口。

## 清理结果：每个文件发生了什么？

执行缓存清理后，点击窗口底部「清理结果」，查看本次启动中最近一次清理的逐文件明细。可以按路径、项目、结果或原因搜索，筛选「未完成 / 已跳过」「已删除」「已保留」。选中一项可复制完整路径和原因，或打开所在目录。

首页会直接显示最近一次清理的文件大小、保留数和未完成数。详情为被占用、权限不足、文件变化等情况说明下一步怎么做。同时测量清理前后该盘可用空间的净变化；其他程序可能同时下载或写入，因此净增加可能少于删除文件大小，甚至净减少。测量失败时明确显示无法读取，不用预计大小替代实测结果。

| 结果 | 含义和处理方式 |
|---|---|
| 已删除 | 同句柄复核和删除请求成功。表格中的「扫描大小」是扫描时长度，不是磁盘新增可用空间。 |
| 被占用 | 相关应用正在运行，或文件不能独占打开。正常退出相关应用后重新扫描。 |
| 权限不足 | Windows 拒绝访问或删除。程序不会接管文件所有权或自动提升权限。 |
| 文件已变化 / 已不存在 | 扫描后内容、身份或路径状态发生变化。重新扫描再判断，不按旧快照强删。 |
| 安全检查未通过 / 规则已变化 | 目录链接、迁移映射、文件属性、最终路径或白名单条件无法再次确认。保留文件并检查其用途。 |
| 手动排除 / 永久保留 | 主动保留，不计为清理失败。 |
| 保留规则不可读 / 已取消 / 未完成 | 本文件没有完成删除，原因栏说明具体情况。 |

明细只包含本轮选中项目内的扫描文件，包括该项目里主动排除的文件；没有选中的项目、完全受保留规则保护的项目，以及扫描时未能读取的文件，不会被伪装成已尝试清理。结果仅保存在内存中，关闭程序即丢弃，没有跨启动的历史记录，也不会上传文件路径。

## 永久保留规则

以下入口会立即保存规则：

- 首页「保护游戏缓存」保护当前用户的 NVIDIA `DXCache`；「保护 EDA / 其他文件夹」让你选择实际目录，「管理保留设置」可查看和移除规则。不会仅凭名称自动猜测所有游戏或 EDA 目录。
- 「文件夹」中选中目录，点击「这个文件夹不清理」。
- 清理前文件预览中选中一行，点击「始终保留选中文件」。它保护当前选中的那一行，不是所有已勾选行。
- 窗口底部「不清理的文件」，输入 C/D 盘绝对路径，选择单个文件或目录及其内容，再添加。可以预先保护尚未创建的路径。

目录规则包含全部后代，同名前缀的相邻目录不受影响。例如保留 `D:\Projects\Example` 不会同时保留 `D:\Projects\Example-copy`。规则同时保存输入路径和添加时解析到的实际路径；路径移动、目录链接改指向后，应重新核对并更新规则。它不按文件内容追踪移动，也不支持通配符。

**规则适用于本工具的缓存删除、卸载后残留回收、回收站清空及迁移检查，不能约束第三方官方卸载器。** 缓存清单会禁用受保护文件的勾选，并从可清理大小中扣除；空间统计仍会计入这些文件。若残留目录与任意保留规则重叠，整次残留回收会被阻止。迁移源或待删除原件、副本受到保护时也会停止。移除保留规则不会立即删除文件，也不会自动勾选原先被取消选择的项目。

规则按 Windows 用户保存到 `%LocalAppData%\DiskGuide\keep-rules.xml`；已重定向的用户目录使用其可核验的实际 C/D 盘位置，管理窗口显示实际存储路径。升级或移动程序时沿用这份设置。该文件包含本机路径，请勿当作公共项目文件上传。

添加和移除使用同目录临时文件及原子替换。每次清理前重新读取规则，并持有独占锁，避免本工具的另一个实例在清理中修改规则。规则损坏、无法读取或无法加锁时停止删除，不静默重置为“无保护”。管理窗口可重新读取修复后的文件；请先备份原文件再手工修复。锁针对本工具实例，不能阻止外部编辑器修改 XML；清理使用开始操作时取得的规则快照。

## 扫描性能与取消

目录大小、空间排行、软件占用、缓存扫描及缓存删除共用一个后台执行队列，同一进程内一次只运行其中一个任务。统计工作线程使用较低优先级，文件遍历定期让出时间；这些措施用于减少同时争抢资源，不保证扫描更快，也不是固定的磁盘带宽限制。

目录统计和空间排行在切换页面后继续运行，包括正在排队的任务。底栏「扫描任务」显示运行或排队中的任务数，点击可返回任务页面；多项任务时优先返回空间排行，其次是目录统计和缓存处理。返回页面保留进度或已完成结果。主动取消、切换磁盘或改变统计范围仍会结束对应的旧任务；重新扫描目录或执行实际清理会使旧目录统计失效。软件占用弹窗关闭后取消其中的统计；关闭整个程序取消未完成扫描。迁移执行期间会阻止直接关闭主窗口，请先取消迁移并等待停止。等待队列中的任务同样可取消，不必等它开始扫描。目录浅层导航和软件/启动项清单读取仍可独立工作。目录大小在本次会话复用，排行榜只保留最大的 100 个文件条目。多个独立程序实例之间不共用扫描队列；Windows 正在处理的单次文件系统调用也不能保证立即中断。

## 空间排行：先找出占用，再判断用途

进入「占用排行」，选择 C 盘或 D 盘，点击「开始统计」。也可以在「文件夹」选中文件夹，点击「查看空间排行」，只统计该目录。整盘统计可能需要时间；按钮可随时取消，切换磁盘或改变统计范围也会取消旧扫描。单纯切换到其他页面不会中断统计。

- 「当前层文件夹」按已读大小排序，包含各直接子目录内的全部可读取文件。选择一项可进入该目录继续统计。
- 「最大文件 Top 100」是所选范围全部层级中最大的 100 个文件。排行榜搜索只过滤已统计结果，不重新遍历磁盘。
- 「打开所在位置」定位文件或目录，不删除。大文件可能是虚拟磁盘、数据库、模型、素材或系统文件，大小不决定是否可以清理。

统计使用文件长度，跳过目录链接和无法读取的位置。显示 `≥` 或跳过数意味着不完整；取消时不展示未完成的排行。子目录排行不含根目录直接文件，而顶部合计和最大文件榜包含它们。遍历只保存最大的 100 个文件条目；统计期间文件可能变化，结果不是文件系统冻结快照，也不等于物理占用或可释放空间。

## 首页清理方案和回收站

首页分别显示建议清理的缓存、需要先了解影响的缓存、正在使用的项目，以及回收站、个人资料迁移入口。未知目录、大文件和软件占用不会混进「一键清理」的预计值。迁移大小需选择文件夹并检查后才能确定。

回收站按所选 C/D 盘单独读取大小与数量。读取失败会说明原因，不显示成零。点击「清空回收站」后仍需确认；通过 Windows 的回收站接口清空该盘，属于永久删除，和普通缓存清理分开执行。回收站范围与保留规则重叠时，整个清空操作被阻止。回收站显示的文件大小也不保证等于最终增加的可用空间。

## 把个人资料迁移到 D 盘

目前支持 **C 盘桌面、文档、下载、图片、音乐、视频中的子文件夹**，不支持整个个人目录根目录。D 盘须是本地固定 NTFS 磁盘，容量须够放副本并预留 512 MB。迁移目标显示在窗口中，形如 `D:\DiskGuideMoved\任务编号\原文件夹名`，每次任务独立存放，避免覆盖已有数据。

1. **检查大小与占用**：核对目录范围、保留规则、文件数量与状态。单次最多 10 万个文件，超出请分批选择子文件夹。
2. **复制并校验**：复制到 D 盘，逐文件核对身份和 SHA-256 内容；空目录也保留。此时显示「已复制并校验」，C 盘原件还在，尚未释放空间。
3. **切换原路径**：再次校验，将原件改名为同级的回退目录，再建立 C 盘原路径到 D 盘的目录联接。切换后从原来的路径访问 D 盘数据，原件仍保留。
4. **验证可用**：从原路径打开资料或项目，确认能正常使用。验证期间不要编辑文件；两份内容不一致时程序会停止删除，避免覆盖或丢失修改。
5. **确认删除原件**：只有你点击「我已验证可用，删除原件…」并确认，才再次校验并删除 C 盘回退原件。每个文件删除前还会锁定原件和副本、核对身份与内容。最后只删除已经为空的回退目录。

切换后、尚未开始删除原件时，可以选择「恢复 C 盘原路径」。恢复也需要两份内容一致，D 盘副本会保留。取消、复制失败或校验失败不会自动清除副本；中断的复制会保留当前副本，重新检查时建立新任务，不覆盖旧副本。关闭后重新打开迁移窗口可核对最近任务；正在执行时须先取消并等待停止。

**此功能不迁移 Windows、Program Files、AppData、运行中的 Codex 配置数据库或任意软件安装目录。** 应用数据优先使用各自的存储位置设置。目录或文件包含链接、硬链接、只读/系统属性、加密、云端占位或附加数据流等不支持状态时，会保留原件并解释原因。工具不强制结束软件进程，也不复制原目录的自定义权限；D 盘目标限制为当前用户、SYSTEM 和管理员访问。需要保留专用共享权限的资料应使用适合该场景的迁移工具。

完成后 **D 盘目标是正式数据，C 盘原路径是访问入口，两者都应保留**。不要把 D 盘目标当成可删除备份。复制和 SHA-256 校验不是独立备份；重要资料仍应有另外的备份。

迁移记录保存在本机设置目录中的 `keep-rules.transfer.xml`，各任务记录另存于 `Transfers`。记录包含路径、文件身份和校验值，不含文件正文，不会上传。不要在任务未完成时删除记录或手动更改映射。

## 查看哪些位置又变大了

每次缓存扫描或空间排行完成后，保存可完整读取位置的大小。首页空间变化入口比较 **同一范围的最近两次完整记录**，显示当前大小、增减和两个扫描时间。首次显示「首次记录」，扫描取消、读取不完整的位置不用于推断增长或减少。缓存与文件夹统计分开保存，不相加；缓存记录统计的是符合规则的文件，文件年龄跨过阈值也可能影响数字。

记录保存在本机 `keep-rules.growth.xml`，最多保留最近 2,000 个位置，每个位置保留最近比较值。仅在用户扫描时记录，没有常驻后台监控、定时全盘扫描或联网上传。清除历史只删除比较记录，不删除磁盘文件。持续增长时可打开该位置，按对应软件自己的缓存/下载设置调整保存位置。

## 按软件查看 C、D 盘占用

在「已装软件」选中一项，点击「查看 C / D 盘占用」。这个窗口按需进行只读统计，关闭即取消。安装器的「参考大小」与这里的实测大小分开呈现。

| 位置来源 | 如何解释 |
|---|---|
| 卸载登记的安装位置 / Windows 包安装位置 | 标为「登记关联」。登记关联不等于能证明目录内每个文件都由该软件独占。与其他软件登记目录重叠或登记读取不完整时，改为待核对。 |
| 商店包数据目录 | 使用 Windows 返回的精确 `PackageFamilyName` 定位当前账户的 Packages 子目录，展示配置与用户数据的混合占用。 |
| 已知产品数据目录 | 对 Chrome、Edge、豆包、抖音、百度网盘、Clash Verge、Docker Desktop 的识别名称匹配已知目录模板，明确标为「待核对」，不授予删除权限。目录可能同时含配置、缓存、历史记录或用户数据。 |
| 已有缓存规则目录 | 在上级数据目录下补充展示已识别的缓存/日志位置。其目录大小不是当前可清理大小，清理资格仍以缓存清单为准。 |
| 卸载器所在目录 | 没有安装位置登记时，仅将可识别的本地卸载器目录列为候选；不能直接当作完整安装目录。 |

每行显示原路径、实际路径和归属依据。只解析这些明确候选根目录的链接，随后在实际 C/D 盘目标中统计；递归遍历内部仍跳过链接。相同实际目录和嵌套目录不重复合计，硬链接文件仍可能按不同文件名重复计数。共享根目录不会被当成一个软件的空间占用。

**这些是已发现位置，不是全盘所有关联数据。** 自定义保存目录、便携软件、未知产品布局及其他用户数据可能缺失。登记关联和待核对位置分别合计，部分不可读时标为已读下限；没有位置时显示无法统计。此窗口没有直接删除入口。

## 开机启动：为什么关了自启动还在运行？

启动页默认只显示能确认「已开启」的常见软件，并提供「已关闭」「待确认」分类。三个分类分别显示数量，搜索只影响当前列表，不改变分类总数。状态无法识别的记录放在「待确认」，不会猜成已开启或已关闭。

计划任务和后台服务收在「高级查看」中，分别查看、单独计数，不计入常见软件数量；点击「返回常见软件」回到原来的状态分类。可以搜索名称、启动命令或登记位置，选中记录后展开查看原始位置。清单的读取范围与 Windows 设置不同，数量不保证完全相同。

| 来源 | 读取方式与状态含义 |
|---|---|
| Run / RunOnce | 只读当前用户和本机注册表；本机兼顾 32/64 位视图。RunOnce 单独标记一次性执行。 |
| 启动文件夹 | 当前用户及公共启动文件夹；快捷方式展示原文件位置，不执行快捷方式。 |
| 计划任务 | 通过 Task Scheduler COM 读取含开机或登录触发器的任务，包括隐藏和禁用任务。分别显示任务/触发器是否启用以及当前是否运行。 |
| 自动服务 | 读取自动启动的 Win32 服务及延迟启动标志；不把启动配置当作实时运行状态。 |

**禁用下次启动不会自动结束已运行的进程。** 例如一个计划任务可以同时显示「任务已禁用」和「当前运行中」。任务已启用也可能受账户、电源、日期等条件限制。登录启动项的 `StartupApproved` 是 Windows 未公开格式，本工具只解释明确识别的状态；缺失、未知值及无法确认的一次性启动记录归入「待确认」，详情保留原始说明。

本页不修改注册表、任务或服务。三个管理入口分别打开 Windows 启动应用设置、任务计划程序和服务管理，由用户在系统界面操作。它不是完整的持久化机制审计：组策略、WMI 订阅、驱动等不在此清单内；其他账户的专属项也可能不可读。读取失败会提示清单不完整。[微软登录启动说明](https://learn.microsoft.com/en-us/windows/win32/setupapi/run-and-runonce-registry-keys) · [微软任务触发器说明](https://learn.microsoft.com/en-us/windows/win32/taskschd/starting-an-executable-when-a-user-logs-on)

## 软件管理与卸载

输入名称、发布者或安装路径即可筛选。桌面软件来自当前用户和本机的卸载登记（含 32/64 位）；商店应用通过 Windows PowerShell 的 `Get-AppxPackage` 查询当前用户。列表包含可读取的框架、资源包等，但受保护项目不能在本工具中卸载。未登记的免安装软件、其他用户独占的应用和部分驱动不会被完整列出，因此不能把列表当作全盘所有可执行文件的全集。

卸载流程：

1. 选择软件，点「卸载这个软件」，核对名称、发布者、版本、安装位置后确认。
2. 桌面软件调用重新核验后的官方卸载程序；MSI 按精确产品 GUID 卸载并禁止主动重启。商店包通过固定脚本移除精确包标识，参数不拼接进脚本文本。软件可能显示自己的卸载或 UAC 提示；官方卸载器也可能删除设置、存档，请先保存需要的内容。
3. 重新读取软件登记。仅窗口退出或进程返回不算卸载成功；仍有登记时提示继续完成或检查结果。需要重启时本轮不清理残留，也不会代替用户重启。
4. 卸载结束后自动核对，结果直接显示在软件页面下方，不弹出结果窗口，也不需要点击「检查卸载结果」或「关闭记录」。未确认完成时，顶部「重新扫描」会更新结果。没有找到安装位置时，会说明无法判断残留，不代表所有文件都已清除。
5. 只有确认可处理的安装残留，才显示「查看可清理的残留」。主动点击后才打开文件清单，回收前仍需确认。仅在路径独占、没有链接/共享目录，且内容可识别为程序文件时提供额外清理；配置、文档、未知文件或读取失败时保留。

残留文件在再次确认后，使用 Windows `IFileOperation` 明确要求移至回收站；不可回收或报错时停止，没有永久删除后备操作。只向 Shell 提交预览中的具体文件，不递归提交整个目录；对文件身份及清单重新核验，回收后只移除身份匹配且已经为空的目录。新出现的文件会使目录保留。此步骤不能代替先保存个人数据，也不能控制第三方官方卸载器的行为。[Windows 文件操作标志](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-ifileoperation-setoperationflags)

**不能保证一键删除某个软件在所有磁盘上的“所有东西”。** 任意目录里的个人文件、下载内容、项目、共享运行库、浏览器数据和其他应用共用的注册表项，无法只凭软件名称可靠归属。本版本不按模糊名称全盘删除，也不清扫未知注册表项。商店包由 Windows 管理共享包与数据，卸载后不对 `WindowsApps` 进行手工清除。[微软应用卸载说明](https://support.microsoft.com/en-gb/windows/apps/uninstall-or-remove-apps-and-programs-in-windows) · [Remove-AppxPackage 文档](https://learn.microsoft.com/en-us/powershell/module/appx/remove-appxpackage)

软件清单的「参考大小」是安装器提供的估计值，未登记不等于零，也不代表可以释放同样多的空间。扫描和查看无需管理员权限；某些官方卸载和系统管理操作会由 Windows 要求提升权限。

## 哪些内容会进入清单？

| 文件类别 | 默认选择 | 匹配和取舍 |
|---|---|---|

| 浏览器和桌面应用的网页缓存 | 相关应用退出后勾选 | 支持指定布局的 Chrome、Edge、豆包、抖音、百度网盘缓存。只匹配缓存块、索引等已知文件名，不会对整个浏览器配置目录执行删除。 |
| Clash Verge 历史日志 | 符合条件时勾选 | 指定日志目录及其 `service` 子目录下，最后修改满 7 天的 `.log` 文件。订阅和代理配置保留。 |
| NVIDIA 着色器缓存 | 手动勾选 | 仅匹配指定 `DXCache` 目录和符合命名规则的 `.nvph` 文件。清理后游戏可能需要重新编译着色器。 |
| 应用崩溃转储 | 手动勾选 | 仅匹配用户 `CrashDumps` 第一层满 7 天的 `.dmp`。仍在排查闪退时应保留。 |
| NVIDIA App 更新下载包 | 手动勾选 | 只匹配 `UpdateFramework\ota-artifacts` 中满 7 天且名称符合 NVIDIA 安装包规则的 EXE/ZIP；不包含游戏着色器缓存，不删除正在使用的驱动。 |

| npm 内容缓存 | 手动勾选 | 仅 `_cacache\content-v2\sha512` 下符合分层哈希布局、满 7 天的内容文件；配置和项目文件保留。 |

数据库、工程源码、EDA 历史、个人文档和离线视频没有自动删除规则；未知安装包和历史软件目录也不会仅凭名称被删除。新增更新包与开发缓存默认都不勾选，相关进程运行时保留。不同电脑看到的清单会不同，取决于已安装的应用、目录布局、文件年龄、访问权限和正在运行的进程。文件夹名称含有 `Cache`、`Temp` 或 `-old`，本身不会让它获得删除资格。

**已迁移到 D 盘的应用数据。** 对支持的 Roaming 应用，程序先验证当前账户的实际应用目录是否指向预期的 D 盘目标。验证通过才扫描目标里的指定缓存，删除前还会复核映射。即使另一台电脑上存在相同名称的备份目录，也不能仅凭路径相似进入清理清单。

| [回归测试](源码/Check.cs) | 在专用临时目录造出缓存、个人文件、占用文件、硬链接、目录联接和被替换的文件，检验哪些应删、哪些应留下；覆盖永久保留、损坏配置、并发锁、队列取消与实际 WPF 交互。测试使用独立设置文件。 |

删除过程可以用一个例子理解。假设扫描时找到一个旧的 `example.tmp`，用户随后用同名文件替换了它。点击清理时，程序会检查路径各级目录，尝试独占打开文件，核对卷号、文件标识、长度、修改时间、链接数和句柄对应的最终路径。任一检查失败就跳过。复核通过后，通过**同一个已验证的句柄**提交删除请求，避免按路径重新打开时误删另一个文件。[Windows 最终路径接口](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-getfinalpathnamebyhandlew) · [Windows 文件信息接口](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-setfileinformationbyhandle)

工具在本机工作，扫描无需登录，目录、软件和启动项清单不会上传到 GitHub。普通权限无法读取的位置保持「访问受限」。目录统计使用逻辑文件长度，硬链接可能按多个名字计数，因此删除报告里的文件大小与磁盘可用空间增量可能不同。上述同句柄删除保护指缓存清理器；官方卸载器由第三方提供，Windows Shell 的残留回收是独立流程，不能视作具有完全相同的原子性保证。

例如，一个文件夹中有 2 GB 数据，而当前只匹配 100 MB 网页缓存。「占用空间」显示已读到的约 2 GB，「可清缓存」显示 100 MB。即使进入该目录的清单并执行一键清理，其余约 1.9 GB 仍保留。若应用重新打开、某个文件被占用，实际删掉的还会更少。

## 从源码构建、测试和打包

在具备桌面组件、.NET Framework 4.8/4.8.1 和 PowerShell 的 64 位 Windows 上，打开仓库根目录。此项目使用 Windows 自带的 .NET Framework C# 编译器构建，仓库目录可自行命名。

```powershell
# 构建并运行回归测试，生成根目录的“磁盘清理助手.exe”
powershell -NoProfile -ExecutionPolicy Bypass -File ".\源码\Build.ps1" -Check

# 生成经过检查的便携发布包
powershell -NoProfile -ExecutionPolicy Bypass -File ".\Release.ps1"
```

`-ExecutionPolicy Bypass` 只应用于这次启动的 PowerShell 进程。发布产物在 `dist` 中。可将下载文件的 SHA-256 与同一发布页的 `SHA256SUMS.txt` 对照，检查传输完整性。

```powershell
Get-FileHash ".\DiskGuide-1.10.0-windows.zip" -Algorithm SHA256
```

发布包使用普通 Windows 桌面可执行文件，目前没有 Authenticode 代码签名。请从本仓库的 Releases 下载并核对校验值。维护者向 main 推送或提交拉取请求时，GitHub Actions 会在 Windows runner 上执行构建、测试和打包。CI 通过只说明该环境中的检查通过，其他 Windows 版本仍需分别验证。

## 图标和操作状态的实现说明

图标来自桌面软件的 `DisplayIcon` 登记、启动程序或快捷方式，以及商店应用的本地清单资源。列表先显示，再逐项补齐图标；不能读取、路径已失效或没有登记图标的项目显示统一占位图标。只读取本地固定磁盘，不联网下载图标，不运行启动命令；目录链接、网络路径及无法识别的资源会跳过。因此并非每个项目都能显示品牌图标，图标也不作为软件身份或安全性的证明。

动画不代表完成百分比。官方卸载器打开后仍需按其提示操作，程序随后核查登记与残留；被占用、跳过、要求重启或无法确认的情况会保留说明，不以卸载器窗口关闭判断成功。多个操作分别跟踪，窗口最小化或关闭时停止动画；关闭 Windows 客户区动画时使用静态状态提示。

## 版本记录

v1.10.0 完成首页分项清理方案、显眼的游戏缓存与文件夹保护、个人资料迁移向导、清理结果和磁盘净变化、六类需手动确认的更新/开发缓存，以及跨启动的空间变化记录。迁移需用户验证后再次确认才删除原件，不支持系统、安装目录或运行中的应用配置。新增文件变化、占用、链接、中断恢复与界面检查。

v1.9.1 使用新的蓝色磁盘清理图标，统一程序文件、窗口、任务栏和界面标识。Windows 图标内置多个尺寸，透明背景图片随程序嵌入，无需额外资源文件。

v1.9.0 将开机启动分成已开启、已关闭、待确认，默认只看已开启的常见软件。计划任务与后台服务移到高级查看，不再混入默认列表和数量。未知状态保守归类，搜索与各类计数分开，并适配小窗口。

v1.8.1 把卸载结果直接放在软件页面下方，移除独立提示栏和手动检查、关闭记录按钮。自动检查不会打开弹窗，残留清单仅在主动点击后展示。结果不会阻止继续管理其他软件。


v1.8.0 增加普通用户首页、日常用语和可展开的详细信息。界面使用常见的 KB / MB / GB 单位名称，大小按每级 1024 换算，便于与 Windows 中的显示比较。首页只汇总当前盘可处理的建议清理项，不包含需单独确认、正在使用或已设为保留的文件。

v1.5 增加逐文件清理结果、跨会话永久保留规则，以及大型扫描任务的排队和取消。五个页面分别用于浏览目录、查找大文件、清理缓存、盘点启动来源和管理软件。启动项和软件按本机范围显示，不受 C/D 盘选择限制。

v1.6.0 修复切换页面中断目录统计和空间排行的问题，加入始终可见的扫描任务入口。UI 参考火绒官方公开界面的窄侧栏和功能分区，采用深蓝导航、浅色内容区与蓝色操作按钮；不使用火绒标识或图稿。参考来源：[火绒官方界面展示](https://www.huorong.cn/document/info/productions/1655.html)。

v1.7.0 为开机启动、软件管理列表加入本地软件图标，并在底部显示清理、读取清单、官方卸载和残留回收的操作动画。切换页面仍可看到进行中的操作；结束后显示完成或需要查看的结果，8 秒后自动收起，也可手动收起。清理详情仍可从「清理结果」查看，卸载详情保留在软件页面。
